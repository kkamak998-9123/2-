# Financial(금융업) — 은행·증권·보험·카드/캐피탈

**문서 상태**: 스펙 초안 (데이터 수집 전). 반도체/건설/방산과 동일한 웹앱 대시보드에 4번째 산업으로 통합 예정.
**대상 범위**: 은행/지주, 증권, 보험(생보·손보), 카드/캐피탈(여신전문금융업) — 상장 금융업 전체, KSIC 업종코드 기준 자동 수집.

---

## PART 0. 이 업종이 기존 3개 산업(반도체/건설/방산)과 다른 점

일반 제조업은 K-IFRS 1001(재무제표 표시)의 표준 서식을 따르지만, 은행·증권·보험·여전사는 업권 감독규정(은행업감독규정, 금융투자업규정, 보험업감독규정)에 따른 **별도 계정과목 체계**를 씁니다.

- **"매출액" 개념이 없음** — 업권마다 대응 개념이 다름(은행: 이자수익, 증권: 순영업수익, 보험: 보험수익). `ratios.py`의 기존 `compute_*` 함수처럼 `acc.get("매출액")` 한 줄로 시작할 수 없고, 업권마다 계정 매핑을 새로 정의해야 함.
- **재무상태표가 유동/비유동으로 안 나뉨** — 은행·증권은 유동성 순서 배열(K-IFRS 1001 §60 예외). 건설업에 썼던 "유동비율" 같은 지표는 성립하지 않음.
- **핵심 규제비율이 재무제표 본문에 없음** — BIS비율, 지급여력비율(K-ICS), NCR 등은 사업보고서의 "재무에 관한 사항" 또는 "경영지표" 섹션에 텍스트/표로만 존재. dart-fss 표준계정 API(`fs.extract` 등)로는 못 가져오고 **사업보고서 원문 파싱이 필수**.
  → 반도체 모듈에서 EBITDA를 외부 데이터로 수동 입력했던 것과 같은 성격의 보강이 전 업권에 필요함. 이 프로젝트는 그 보강을 "사업보고서 파싱"으로 자동화하는 것이 핵심 과제.

## PART I. 대상 기업

### 1.1 수집 방법론

기존 산업(반도체/건설/방산)은 팀원이 직접 A/B/C 그룹으로 큐레이션했지만, 금융업은 **KSIC 업종코드 기반 자동 수집**으로 결정.

- dart-fss의 상장기업 코드 목록(`dart_fss.get_corp_list()`)에서 KSIC 대분류 **K(금융 및 보험업)** 소속 기업을 필터링
- ⚠️ **TODO(검증 필요)**: KSIC 세세분류 코드(예: 은행=64xx, 보험=65xx, 금융서비스=66xx)를 기억에 의존해 하드코딩하지 않는다. 실제로는 dart-fss에서 받아온 기업별 `induty_code`/업종명 원본 값을 먼저 전수 조회해서, 4개 서브섹터로 분류하는 매핑 테이블을 코드 작성 단계에서 직접 확정한다.
- 지주회사(금융지주 vs 일반 사업지주)는 KSIC만으로 구분이 애매할 수 있어, 회사명에 "금융지주"가 포함되거나 대표 자회사가 은행/증권/보험인 경우로 보조 필터링 필요.

### 1.2 4개 서브섹터 분류 기준

| 그룹 | 정의 | 비고 |
|---|---|---|
| **은행/지주** | 은행업 인가 기업 + 금융지주회사 | 지주는 연결 기준 자회사 포트폴리오 다양(은행+증권+보험+카드) |
| **증권** | 금융투자업(투자매매업·투자중개업) 인가 증권사 | 자산운용사·선물사는 1차 범위에서 제외(사업보고서 의무 대상 상장사 위주) |
| **보험** | 생명보험·손해보험 사업자 | 생보/손보는 손익 구조가 달라(손해율 개념은 손보 전용) 서브 태그로 구분 |
| **카드/캐피탈** | 여신전문금융업(신용카드업, 할부금융업, 리스업) | 예수금이 없는 게 은행과의 핵심 차이 |

### 1.3 수집 연도 범위

기존 산업과 동일하게 **최근 2개 연도(2024, 2025)** 기준으로 시작. 보험업은 2023년 IFRS17 전면 도입으로 그 이전 연도와 수익 인식 기준이 달라 단순 비교가 왜곡되므로, 2023년 이전 데이터는 별도 표기 없이 섞지 않는다.

## PART II. 업권별 분석 설계

### 2.1 은행/지주

**2.1.1 필요 데이터**

- (재무제표 API로 확보 가능) 이자수익, 이자비용, 수수료수익, 대손충당금전입액, 판매비와관리비, 당기순이익, 대출채권, 예수금, 자산총계, 자본총계
- (사업보고서 원문 파싱 필요) BIS총자본비율, 보통주자본비율(CET1비율), 순이자마진(NIM), 고정이하여신비율(NPL비율), 대손충당금커버리지비율, 원화예대율, 유동성커버리지비율(LCR)

**2.1.2 계산 지표**

| 지표 | 산식 | 의미 | 확보 경로 |
|---|---|---|---|
| 순이자이익(NII) | 이자수익 − 이자비용 | 핵심 본업 수익 | 재무제표 |
| ROE | 당기순이익 / 자본총계 | 자기자본 수익성 | 재무제표 |
| ROA | 당기순이익 / 자산총계 | 총자산 수익성 | 재무제표 |
| CIR(영업이익경비율) | 판관비 / (순이자이익+수수료손익) | 비용효율성 | 재무제표 |
| 대손비용률 | 대손충당금전입액 / 대출채권 | 여신 건전성 부담 | 재무제표 |
| **NIM** | (이자수익−이자비용) / 운용자산평잔 | 이자마진 수익성 | 사업보고서 |
| **BIS총자본비율** | 자기자본/위험가중자산 | 자본적정성(규제) | 사업보고서 |
| **고정이하여신비율(NPL)** | 고정이하여신 / 총여신 | 부실여신 비중 | 사업보고서 |
| **대손충당금커버리지비율** | 대손충당금 / 고정이하여신 | 부실 대비 충당 수준 | 사업보고서 |
| **원화예대율** | 원화대출금 / 원화예수금 | 조달-운용 균형(규제 상한 100%) | 사업보고서 |

**2.1.3 이상징후 예시**

- NPL비율 상승 + 대손충당금커버리지비율 하락 → 부실 확대에 충당이 못 따라가는 상태
- 순이익 증가 + NIM 하락 지속 → 이자마진 압박을 비이자이익(수수료 등)이 가려주는 구조, 지속가능성 의문
- BIS비율 규제 최저선(예: 총자본비율 8%) 근접 → 자본확충 압박 신호

### 2.2 증권

**2.2.1 필요 데이터**

- (재무제표) 수수료수익(위탁매매/IB/자산관리), 자기매매손익, 이자손익, 당기순이익, 자본총계, 트레이딩증권, 투자자예수금
- (사업보고서 파싱 필요) 영업용순자본비율(신NCR), 위탁매매 시장점유율

**2.2.2 계산 지표**

| 지표 | 산식 | 의미 | 확보 경로 |
|---|---|---|---|
| **순영업수익** | 수수료손익+자기매매손익+이자손익 (매출액 대용) | 본업 전체 규모 | 재무제표 |
| 수수료수익비중 | 수수료손익 / 순영업수익 | 안정적 수익원 비중 | 재무제표 |
| 트레이딩손익비중 | 자기매매손익 / 순영업수익 | 시장변동성 노출도 | 재무제표 |
| ROE | 당기순이익 / 자본총계 | 자기자본 수익성 | 재무제표 |
| **신NCR** | 영업용순자본 / 총위험액 | 자본적정성(규제, 100% 하한) | 사업보고서 |

**2.2.3 이상징후 예시**

- 트레이딩손익비중 급등 → 이익의 질이 시장베타에 크게 의존, 다음 분기 반전 위험
- 순영업수익 증가 + 당기순이익 정체 → 비용(인건비·판관비) 증가 또는 대손 반영 가능성
- 신NCR 규제선 근접 → 신규 위험자산 확대 여력 축소

### 2.3 보험(생보·손보)

**2.3.1 필요 데이터**

- (재무제표, IFRS17 기준) 보험수익, 보험서비스비용, 보험손익, 투자손익, 당기순이익, 보험계약부채, 계약서비스마진(CSM), 자본총계
- (사업보고서 파싱 필요) 지급여력비율(K-ICS), 손해율·사업비율·합산비율(손보 전용)

**2.3.2 계산 지표**

| 지표 | 산식 | 의미 | 확보 경로 |
|---|---|---|---|
| 보험손익 | 보험수익 − 보험서비스비용 | 보험영업 자체 손익 | 재무제표 |
| ROE | 당기순이익 / 자본총계 | 자기자본 수익성 | 재무제표 |
| CSM 잔액 대비 자본비율 | CSM / 자본총계 | 미래이익 곳간 규모 | 재무제표 |
| **K-ICS 지급여력비율** | 가용자본/요구자본 | 자본적정성(규제, 100% 하한, 권고 150%) | 사업보고서 |
| **손해율**(손보) | 발생손해액 / 경과보험료 | 보험금 지급 부담 | 사업보고서 |
| **사업비율**(손보) | 순사업비 / 경과보험료 | 판매·관리 비용 부담 | 사업보고서 |
| **합산비율**(손보) | 손해율+사업비율 | 100% 초과 시 보험영업 자체는 적자 | 사업보고서 |

**2.3.3 이상징후 예시**

- K-ICS 지급여력비율이 권고 기준(150%) 밑으로 하락 추세 → 자본확충 압박
- 합산비율 100% 초과 지속(손보) → 보험영업 자체 적자를 투자손익으로 메우는 구조
- CSM 잔액 감소 + 신계약 CSM 유입 둔화 → 미래이익 창출력 저하 신호

**2.3.4 IFRS17 관련 주의사항**

2023년 전면 도입 이전(원수보험료 기준 매출)과 이후(보험수익 기준) 수치가 개념적으로 다르므로, **2022년 이전 데이터를 동일 지표로 이어 붙이지 않는다.** 다년도 추세 분석은 2023년 이후 데이터로만 수행.

### 2.4 카드/캐피탈(여신전문금융업)

**2.4.2 계산 지표**

| 지표 | 산식 | 의미 | 확보 경로 |
|---|---|---|---|
| 조정총자산이익률 | 당기순이익 / 자산총계 | 자산 수익성 | 재무제표 |
| **레버리지배율** | 총자산 / 자기자본 | 조달 여력(감독규정상 상한, 통상 자기자본 10배 내외) | 재무제표 |
| 차입금의존도 | 차입부채 / 자산총계 | 시장성 조달 의존도(예수금 없음) | 재무제표 |
| **연체율**(1개월 이상) | 연체채권 / 총채권 | 자산 건전성 | 사업보고서 |
| **대손충당금적립률** | 대손충당금 / 요적립액 기준 | 규제 충당 적정성 | 사업보고서 |

**2.4.3 이상징후 예시**

- 레버리지배율이 규제 상한 근접 → 추가 성장(신규 카드/할부 취급) 여력 소진
- 연체율 상승 + 차입금의존도 상승 동시 발생 → 조달비용 상승 국면에 자산건전성까지 악화되는 이중 압박
- 조정총자산이익률 하락 + 대손상각비 급증 → 과거 확장기 취급 자산의 부실화 반영 가능성

## PART III. 데이터 수집 방법론

### 3.1 1단계 — dart-fss 표준 재무제표 API

- `dart_fss.fs.extract()` 등으로 CFS(연결) 우선, 없으면 OFS(별도) 사용 — 기존 산업과 동일한 원칙(`FS_DIV_PRIORITY`)
- 업권마다 XBRL 계정명이 다르므로, 업권별 "표준 계정명 후보군" 딕셔너리를 만들어 한글/영문 표기 흔들림을 흡수 (기존 `data_loader.py`의 쉼표·괄호음수·공백 정규화 로직 재사용)

### 3.2 2단계 — 사업보고서 원문 파싱 (신규 작업)

- 대상: 재무제표 API로 못 가져오는 **규제비율**(BIS비율, K-ICS, NCR, 연체율 등)
- 방법: dart-fss로 사업보고서 원문(XML/HTML) 문서 목록을 받아, "재무에 관한 사항" 또는 "경영지표" 관련 절을 텍스트로 추출 → 정규식/표 파싱으로 값 추출
- `자소서 프로젝트/collect_auditors.py` 패턴(세션 재사용 + ThreadPoolExecutor + 재시도 + 중간 저장) 을 데이터 수집 스크립트의 뼈대로 재사용
- 파싱 실패/미기재 항목은 반도체 모듈의 EBITDA 커버리지 표기 방식처럼 **"수집 불가"로 명시**, 0으로 채우지 않음(건설 모듈의 공사손실충당부채 처리 원칙과 동일)

### 3.3 산출 스키마

기존 산업과 동일한 롱포맷 CSV를 목표로 함(`corp_code, stock_code, corp_name, year, fs_div, sj_div, account_name, amount, memo, updated_at`). 서브섹터 구분을 위해 `industry_id`에 `bank`/`securities`/`insurance`/`cardcapital` 4종을 사용.

## PART V. 한계 (웹사이트에 명시 필요)

- **규제비율의 사업보고서 파싱 커버리지는 100%가 아님.** 회사마다 경영지표 공시 서식이 조금씩 달라 정규식이 못 잡는 케이스가 있을 수 있음 → 반도체 모듈의 EBITDA처럼 커버리지 %를 명시.
- **보험업 IFRS17 전환으로 2023년 이전과 이후 수치 비교 불가.**
- **지주회사는 자회사 포트폴리오가 이질적**이라(은행+증권+보험+카드 혼재), 단일 서브섹터 지표로 평가하면 왜곡될 수 있음 → 지주는 별도 태그(`holding`)로 분리할지, 은행 그룹에 포함하되 주석을 달지 이후 확정 필요.
- **KSIC 기반 자동 수집이므로 경계 케이스(예: 핀테크 자회사를 가진 비금융 지주) 오분류 가능성** → 최초 수집 결과를 사람이 한 번 훑어 확인하는 단계 필요.
